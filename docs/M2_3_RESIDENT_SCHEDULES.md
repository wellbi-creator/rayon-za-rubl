# M2.3 — Распорядок жителей

## Цель
Подключить первые ежедневные активности семей к единому GameTime. Расписание работает по игровым часам, а не по реальному системному времени.

## Распорядок стартовой семьи
| Игровое время | Активность | Отображение на карте |
|---|---|---|
| 00:00–06:00 | Сон | Жителей не видно на улице |
| 06:00–08:00 | Дома, утренние дела | Персонажи находятся возле дома |
| 08:00–17:00 | Работа | Персонажи временно не отображаются на карте района |
| 17:00–20:00 | Прогулка | Персонажи двигаются по демонстрационному маршруту |
| 20:00–22:00 | Дома, отдых | Персонажи находятся возле дома |
| 22:00–00:00 | Сон | Жителей не видно на улице |

## Реализация
- ResidentService хранит расписание как набор временных интервалов и активностей.
- update_time(hour, minute, day) вызывается при изменении игрового времени.
- Смена активности обновляет сохранённое состояние семьи и сигнал residents_changed.
- Контекстная панель заселённого дома показывает текущую активность семьи.
- DistrictWorld отображает жителей в зависимости от активности: у дома, на прогулочном маршруте или не показывает их во время сна/работы.
- Активность и её подпись сохраняются вместе с данными семьи; старые сохранения совместимы — состояние вычисляется при следующем обновлении игрового времени.
- Расписание использует игровой масштаб 5 реальных минут = 1 игровой час.

## Границы этапа
- «Работа» пока является расписанием занятости: рабочих мест, зданий предприятий, зарплаты и поездок на работу ещё нет.
- Прогулка использует демонстрационный маршрут; полноценный pathfinding и обход препятствий не реализованы.
- Нет индивидуальных расписаний, выходных, потребностей, сна как ресурса, влияния распорядка на настроение/удовлетворённость или симуляции отношений.
- Нет новых расходов или доходов.
- Godot Editor/runtime не запускался локально. GitHub Actions проверяет проект автоматически, но не заменяет визуальный тест на устройстве.

## Проверки
