# M1.5 — Система строительства

## Назначение

ConstructionService выделяет строительство в самостоятельную игровую систему. Один строительный экипаж может вести один объект; число одновременно активных проектов ограничено числом бригад. Сервис допускает расширение штата через hire_crew().

## Типы домов и длительность

| Тип | Время |
|---|---:|
| Обычный | 10 минут |
| Продвинутый | 30 минут |
| Премиум | 60 минут |

Эти значения централизованы в HOUSE_TYPES. Экономические цены типов домов намеренно не задаются в этом этапе: их нужно согласовать в отдельном балансовом проходе.

## Этапы

1. Подготовка участка
2. Фундамент
3. Стены
4. Крыша
5. Окна и двери
6. Коммуникации
7. Отделка

Стадия определяется по доле общего времени, а прогресс проекта хранится отдельно для каждого участка.

## Сохранение и офлайн-прогресс

get_save_data() возвращает число бригад и словарь проектов. load_save_data() восстанавливает допустимые типы домов, ограничивает прогресс диапазоном длительности и применяет прошедшее офлайн-время. Завершившиеся проекты отправляют сигнал project_completed.

## API

- start_project(plot_id, house_type) — запускает проект, если участок свободен и есть свободная бригада.
- hire_crew() — увеличивает доступную численность бригад.
- get_project(plot_id) — возвращает копию данных проекта.
- get_stage(progress) — возвращает название текущей стадии.
- get_save_data() / load_save_data() — сериализация состояния.

## Ограничения этого шага

- Сервисная основа добавлена отдельно; подключение UI, визуальных стадий на карте, назначения рабочих и строительных материалов требует следующего прохода интеграции.
- Найм пока не списывает деньги: стоимость бригады и зарплата должны быть утверждены в экономическом балансе.
- Проверка в Godot Editor/runtime не выполнялась.
- Построенный дом остаётся отдельным от состояния «готов к заселению»; чек-лист заселения будет отдельной системой.
