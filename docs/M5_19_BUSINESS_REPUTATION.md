# M5.19 — Репутация коммерческих заведений

## Цель
Добавить каждому заведению собственную долгосрочную репутацию, отличную от общей репутации района, и связать её с конкуренцией за существующий поток покупателей.

## Правила
- Новое заведение начинает с репутацией 50 из 100.
- За каждые прошедшие игровые сутки репутация активного бизнеса сдвигается на 1 пункт в сторону текущей средней удовлетворённости жителей района.
- Если в районе пока нет жителей, репутация не меняется.
- Приостановленный бизнес не меняет репутацию.
- Активный арендованный бизнес продолжает менять репутацию, поскольку его обслуживает арендатор.
- Вес заведения в распределении общего потока равен базовым 100 пунктам + бонус улучшений привлекательности + (репутация − 50), минимум 1.
- Репутация не создаёт дополнительных покупателей: она меняет только долю существующего общего спроса.
- UI показывает значение репутации и последнее суточное изменение.

## Сохранения
- Сохраняются `reputation` и `last_reputation_change`.
- Старые сохранения без этих полей получают репутацию 50 и изменение 0.

## Проверки логики
- Границы репутации всегда 0–100.
- Изменение за один игровой день не превышает 1 пункт; при офлайн-прогрессе учитывается каждый прошедший игровой день.
- Остановленные заведения и районы без жителей не меняют репутацию.
- Арендованные активные заведения продолжают её развивать, но не попадают в список собственных точек, делящих выручку.
- Сумма распределённых покупателей остаётся равной общему потоку; репутация влияет только на веса.
- Существующие улучшения привлекательности, аренда и старые сохранения сохраняют совместимость.

## Ограничения проверки
Статические проверки исходников не заменяют запуск Godot, проверку UI на устройстве и GitHub Actions.
