# M2.4 — Потребности жителей

## Цель
Добавить первую сохраняемую симуляцию потребностей семьи, связанную с единым GameTime и ежедневным распорядком.

## Показатели
Все показатели выражаются в процентах от 0 до 100:
- **Энергия** — снижается во время бодрствования и восстанавливается во время сна.
- **Голод** — постепенно растёт как потребность (значение сытости снижается).
- **Гигиена** — постепенно снижается.
- **Досуг** — постепенно снижается между периодами отдыха.
- **Комфорт дома** — стартовая оценка условий жилья; пока сохраняется стабильным, поскольку качество коммунальных услуг и состояние района ещё не подключены.

## Влияние
- Потребности обновляются по игровым минутам, а не по реальному времени.
- При критическом значении любой потребности настроение постепенно снижается.
- При хороших средних показателях настроение может восстанавливаться.
- Удовлетворённость медленно меняется вместе с общим состоянием потребностей; комфорт дома станет полноценным динамическим показателем после появления качества жилья и районных служб.
- Показатели семьи отображаются в контекстной панели заселённого дома.

## Сохранения и совместимость
- Потребности и отметка последней обработанной игровой минуты сохраняются в блоке `residents`.
- Старые сохранения автоматически получают безопасные стартовые значения.
- При загрузке учитывается прошедшее игровое время; обработка офлайн-прогресса ограничена семью игровыми сутками за один catch-up, чтобы не создавать чрезмерную нагрузку.

## Временные настройки прототипа
- Энергия: -0,055 за игровую минуту бодрствования, +0,35 за игровую минуту сна.
- Сытость: -0,10 за игровую минуту.
- Гигиена: -0,045 за игровую минуту.
- Досуг: -0,035 за игровую минуту.
- Настройки являются тестовыми коэффициентами, а не финальным балансом.

## Границы этапа
- Пока нет действий кормления, душа, сна по команде, развлечений, магазинов, бытовой техники и покупки ресурсов.
- Нет расходов или доходов; баланс EconomyService не меняется.
- Комфорт дома пока не деградирует сам по себе.
- Потребности общие для семьи, а не индивидуальные для каждого из трёх жителей.
- Godot Editor/runtime не запускался локально; GitHub Actions проверит изменения автоматически, но не заменяет визуальный тест на устройстве.

## Проверки
GitHub Actions запускается автоматически для PR и после объединения в main.
