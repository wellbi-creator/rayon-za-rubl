# M5.13 — диспетчеризация коммунальных служб

## Цель
Перевести коммунальный штат из пассивной статьи зарплат в действующий инструмент устранения районных проблем.

## Поведение
- При активном районном событии интерфейс определяет профильную службу по типу проблемы.
- Если у службы есть хотя бы один работник, игрок может направить собственную бригаду.
- Если штат пуст, действие обозначается как вызов подрядчика.
- Оба варианта сохраняют существующую стоимость решения и эффекты события; скидка собственной службы рассчитывается её эффективностью по правилам M5.12.
- Работа засчитывается в статистику только при успешном решении события силами собственного штата.

## Учёт и сохранение
Для каждого направления сохраняются:
- количество выполненных работ;
- день последнего выезда;
- суммарные затраты на выполненные работы.

В панели коммунальных служб отображаются общая статистика работ и показатели каждого направления. Данные необязательны при загрузке: старые сохранения получают нулевые счётчики без миграции.

## Границы этапа
Автоматические плановые работы, назначение зон обслуживания, коммунальная техника и долговременное состояние инфраструктуры остаются следующими этапами.
