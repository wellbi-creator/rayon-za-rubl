# M5.20 — Финансовая история коммерческих заведений

## Цель
Дать игроку возможность оценивать эффективность каждого помещения отдельно, а не только видеть общие суточные показатели района.

## Накопительные показатели
- Общее число обслуженных покупателей.
- Общая выручка собственного работающего бизнеса.
- Начисленные операционные расходы, включая ежедневную надбавку за уровни привлекательности.
- Операционный итог: накопительная выручка минус накопительные операционные расходы.
- Для сданного помещения — сумма аренды, начисленная именно по этому договору.

## Правила учёта
- Значения начисляются за каждый прошедший игровой день, включая офлайн-прогресс.
- Для собственных заведений используются те же покупатели и выручка, которые участвуют в общем распределении спроса; дополнительные покупатели не создаются.
- Для арендованного бизнеса собственная выручка и расходы владельца не начисляются; вместо этого отдельно накапливается его арендная плата.
- Накопительные значения сохраняются при приостановке бизнеса и расторжении договора.
- Общий долг по операционным расходам остаётся единым районным показателем; накопленные расходы по заведению отражают начисления, а не только успешно оплаченные суммы.
- Старая запись сохранения без новых полей восстанавливается с нулевыми накопительными показателями.

## UI
- Для собственного бизнеса отображаются накопленные посетители, выручка, расходы и операционный итог.
- Для арендуемого помещения отображаются поступления от конкретного договора и общий доход района от аренды.

## Проверки логики
- Многодневное начисление умножается на число реально прошедших игровых суток.
- Накопления каждого участка не смешиваются с другими участками.
- Пауза бизнеса не стирает историю.
- Договор аренды учитывается отдельно от собственного оборота.
- Старые сохранения загружаются без ошибок и начинают накопление с нуля.

## Ограничения проверки
Статическая проверка исходников не заменяет запуск Godot, GitHub Actions и визуальную проверку на устройстве.
