# M1.8 — Синхронизация визуальных стадий строительства

## Единая последовательность

Игровой прогресс остаётся под управлением `ConstructionService`. Визуальные представления используют один и тот же нормализованный прогресс от 0.0 до 1.0 и следующие пороги:

| Прогресс | Стадия |
|---:|---|
| 0–12% | Подготовка участка |
| 12–28% | Фундамент |
| 28–55% | Стены |
| 55–72% | Окна и двери |
| 72–86% | Крыша |
| 86–96% | Коммуникации |
| 96–100% | Отделка |

Порядок окон и дверей перед крышей соответствует проверенной последовательности 3D-прототипа.

## Реализация

- `ConstructionService.STAGES` — источник названий и порогов стадий для игрового процесса.
- 2D-район отображает окна до появления крыши, используя те же пороги.
- `ConstructionVisuals3D.set_construction_progress(progress)` принимает прогресс реального проекта и постепенно раскрывает соответствующие части 3D-дома.
- Демонстрационный запуск 3D-прототипа использует тот же метод и те же пороги; он не меняет игровую экономику, сроки или сохранения.
- Внешний код может отключить `auto_play_demo` и передавать прогресс из `ConstructionService.project_updated`.

## Совместимость

- Формат сохранений и поля `ConstructionService` не меняются.
- Стоимость, длительность проектов, бригады, офлайн-прогресс и условия завершения не меняются.
- Изменяется только порядок отображения стадий: окна/двери теперь перед крышей.
- Старые сохранения продолжают восстанавливать тот же числовой прогресс; новый визуальный порядок применяется к нему автоматически.

## Проверки

Godot headless validation и Web export выполняются GitHub Actions после открытия PR. Автоматические проверки не заменяют визуальную проверку в Safari на iPhone.
