# M5.11 — Спрос и посещаемость магазинов

## Цель
Связать ежедневную выручку магазина с моделируемым потоком покупателей, не меняя график работы 08:00–20:00 и существующую систему операционных расходов.

## Модель спроса
Число покупателей за игровые сутки рассчитывается при переходе на новый игровой день:
- базовый поток — 80 покупателей;
- каждый житель района добавляет 3 потенциальных покупателя;
- репутация района добавляет до 20 покупателей (0,2 за пункт репутации);
- удовлетворённость жителей корректирует поток относительно нейтрального уровня 50 (0,1 покупателя за пункт);
- погода применяет коэффициент: ясно 1,00; облачно 0,95; дождь 0,85; снег 0,80; туман 0,90; гроза 0,70; жара 0,90.
- минимальный поток — 10 покупателей в сутки.
- средний чек — 200 ₽; дневная выручка равна числу покупателей, умноженному на средний чек.

Показатели населения и удовлетворённости берутся из существующей системы жителей, репутация — из системы прогресса района, погода — из WeatherService. Новая отдельная система населения или репутации не создаётся.

## Экономика и совместимость
- Активные магазины получают выручку по рассчитанному спросу; операционные расходы и механизм задолженности остаются прежними.
- Приостановленные магазины не получают выручку и не начисляют новые расходы, как и раньше.
- При офлайн-прогрессе накопившиеся дни обрабатываются существующим механизмом elapsed_days; для всех дней одного catch-up расчёта используются актуальные на момент обработки показатели спроса и погоды.
- Сохранение дополняется последними значениями покупателей и выручки. Старые сохранения автоматически получают безопасные значения по умолчанию (80 покупателей и 16 000 ₽).
- График работы, визуальные покупатели, строительство, дороги и другие игровые системы не меняются.

## Проверка
- Godot headless import/launch и web export проходят в GitHub Actions.
- Сохранение/загрузка сохраняют последние показатели; старые данные без новых полей загружаются.
