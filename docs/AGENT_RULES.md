# Правила работы ИИ-агентов

## Общий принцип

Владелец проекта принимает ключевые решения и подтверждает слияние Pull Request. Ни один агент не должен самостоятельно менять основную ветку без явного разрешения.

## Роли

- Архитектор/координатор: декомпозиция, контракты модулей, интеграция и ревью.
- Геймдизайнер: игровые циклы, правила и прогрессия.
- Программист: реализация систем в Godot.
- Художник/UI: стиль, сцены, ассеты и интерфейс.
- Сценарист: персонажи, сюжет, задания и диалоги.
- Экономист: цены, доходы, расходы и баланс.
- QA: тест-планы, воспроизводимость ошибок и регрессия.

Один агент — владелец конкретной задачи/набора файлов. Не допускать одновременного редактирования одних и тех же файлов разными агентами без координатора.

## Git workflow

1. Каждая задача выполняется в отдельной ветке от актуальной базовой ветки.
2. Имена веток: `feature/<short-name>`, `docs/<short-name>`, `fix/<short-name>`.
3. Коммиты должны быть небольшими и описательными.
4. Pull Request содержит цель, список изменений, тесты, скриншоты/видео при визуальных изменениях и известные ограничения.
5. Перед PR проверить diff, отсутствие случайных файлов/секретов и тесты.
6. Владелец проверяет PR и сам решает, когда сливать.
7. Не переписывать чужую историю и не выполнять force push без явного согласования.

## Код и архитектура

- Следовать существующим соглашениям проекта.
- Использовать типизацию там, где она повышает надёжность.
- Не помещать игровую логику внутрь UI.
- Не дублировать источники истины для денег, времени и состояния объектов.
- Не добавлять зависимости без обоснования.
- Добавлять тесты к критической логике.
- Не заявлять, что сборка/тесты прошли, если они фактически не запускались.

## Контент и ассеты

- Соблюдать единый арт-гайд и масштаб.
- Указывать происхождение и лицензию внешних ассетов.
- Не использовать материалы, права на которые не подтверждены.
- Временные ассеты явно обозначать.
- Сохранять исходники и понятные имена файлов.

## Безопасность

- Никогда не коммитить токены, пароли, ключи, личные данные и секреты.
- Не отключать защитные проверки ради прохождения CI.
- Не менять настройки репозитория, права и секреты без разрешения владельца.

## Отчёт по задаче

Каждый агент сообщает: что сделано, какие файлы изменены, какие проверки запущены и их результат, что осталось, риски и следующий рекомендуемый шаг.
